# iPhone Use

[中文](README.md) · [English](README.en.md) · **日本語**

![Codexから実機のiPhoneを操作し、画面をリアルタイムに表示する例](assets/iphone-use-demo.png)

USBで接続した自分のiPhoneを、Codexから自然言語で操作できます。アプリを開く、画面を読む、タップする、スクロールする、文字を入力する、リストを整理する、といった作業に対応し、サイドバーにiPhoneの画面を表示します。

日本語の画面・ツール説明・スキルを使うには、インストール時に`--language ja`を指定します。引数なしの通常インストールは、従来の言語と案内を維持します。

[WebDriverAgent](https://github.com/appium/WebDriverAgent)（WDA）を介してiPhoneと通信します。ローカルのMCPサーバー、導入・操作用スキル、リアルタイム画面ウィジェットを含みます。既存の接続やビルドを再利用し、要素を特定できないときはスクリーンショットを確認して座標によるタップを試します。

プラグインは既定でPostHogに匿名の利用統計（起動、ツール呼び出し、接続状態、所要時間、エラーの種類）を送信します。ランダムなインストール識別子を使い、iPhoneの画面、入力内容、端末識別子は送信しません。`IPHONE_USE_ANALYTICS=0`または`DO_NOT_TRACK=1`を設定してMCPサービスを再起動すると無効にできます。詳細は[統計について](ANALYTICS.md)を参照してください。

**利用前に、自分のiPhoneでWDA Runnerを署名・インストール・起動する必要があります。** WDAはiPhone側で操作を実行するサービスです。以下の導入手順とセットアップ用スキルでCodexが初期設定を支援します。正常な既存のWDAがあれば再利用できます。

## Codexに導入を依頼する

Mac上のCodexに次のように依頼してください。下記のリポジトリから取得します。すでにクローンまたはZIPを展開済みの場合は、URLの代わりにそのローカルディレクトリを指定できます。

```text
iPhone Useをインストールして設定してください：
https://github.com/zhongerxin/iPhone-use

最初にREADMEとインストールスクリプトを読んでください。
Codex CLI、Python、Node.js、npm、完全版Xcode、USB接続したiPhoneを確認し、
このリポジトリを適切なローカルディレクトリにクローンしてください。
そのディレクトリで sh scripts/install.sh --language ja を実行してください。

このチャットで新しいツールを読み込めない場合は、再接続または新しいチャットが
必要なことを明示してください。ツールが使えるようになったら
iphone-use-setupスキルを読み、既存の設定と正常なWDAを優先して再利用してください。
初回設定では私の端末を検出し、私自身のApple開発チームと署名可能なbundle IDを使い、
固定バージョンのWDAの取得、署名設定、ビルド、起動を行ってください。
pua_readyがready=trueを返すまで進め、その後iPhoneの画面を表示してください。
作者の端末IDや署名情報を流用しないでください。

不足している依存関係は具体的に説明し、導入を手伝ってください。
Appleアカウントへのログイン、端末の信頼、デベロッパモード、ロック解除など
私自身の操作が必要な場合は、手順を説明し、完了を待ってから続けてください。
```

プラグインをインストールした後、新しいツールを読み込むためにチャットの再接続が必要になる場合があります。Appleアカウントへのログイン、端末の信頼、デベロッパモード、ロック解除は、所有者がシステム画面で行います。リポジトリにはGitHubのアクセス権が必要です。取得済みのソースパッケージも利用できます。

## 必要な環境

| 環境 | 用途 |
| --- | --- |
| macOSとCodexデスクトップ版／CLI | ローカルプラグイン、MCPサーバー、画面サイドバー |
| 初回起動設定を完了した完全版Xcode | WDAのビルド・署名・インストール・起動。Command Line Toolsだけでは不足 |
| Xcodeで使用できるAppleアカウントと開発チーム | iPhone上のWDA Runnerへの署名 |
| USBで接続した実機のiPhone | Macを信頼し、必要なデベロッパモードを有効化。導入・起動時はロックを解除 |
| Python 3.9以降 | 標準ライブラリを使うMCPサーバーの実行 |
| Node.js 20.19以降、22.12以降、または24以降／npm 10以降 | USBポート転送と画面ストリーミング。詳細はプロジェクトのenginesとdoctorの診断を参照 |

Xcodeは端末のiOSバージョンに対応している必要があります。脱獄やAppium Serverの別途起動は不要です。セットアップでは上流で検証されたWDA 16.14.0の固定コミットを使い、取得、依存関係の導入、署名、ビルドをローカルで管理します。

## 自分のiPhoneでWDAを起動する

iPhone側では[Appiumが保守するWebDriverAgent](https://github.com/appium/WebDriverAgent)を使います。初回は自分のAppleアカウントと開発チームで`WebDriverAgentRunner`を署名し、インストール・起動します。

上の依頼文と`iphone-use-setup`を使うと、Codexが固定バージョンのWDAの取得、端末・署名の設定、ビルド、インストール、起動を進めます。本人の操作が必要な場面では具体的な手順を案内します。

Xcodeで手動設定する場合：

1. USBでiPhoneを接続し、Macを信頼します。必要に応じてデベロッパモードを有効にし、Xcodeに自分のAppleアカウントを設定します。
2. WDAの`WebDriverAgent.xcodeproj`を開き、`WebDriverAgentRunner`のschemeと自分のiPhoneを選択します。Runner targetの **Signing & Capabilities** で自分のTeamと署名可能なBundle Identifierを指定します。
3. **Product → Test** でビルド・インストール・起動します。iPhoneに表示される信頼の確認を完了します。インストール後もWDAサービスが動作している必要があります。

プラグインの導入とUSB接続設定後、`pua_ready`が`ready=true`を返してからiPhone上の作業を始めます。端末・署名の詳細は[Appiumの実機準備ガイド](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/device-setup/)を参照してください。

## インストールと接続

```sh
git clone https://github.com/zhongerxin/iPhone-use.git
cd iPhone-use
sh scripts/install.sh --language ja
```

ZIPから展開した場合も、展開したフォルダーで`sh scripts/install.sh --language ja`を実行します。ソースパッケージには通常版と日本語版の両方の翻訳・ビルド成果物が含まれます。

このオプションはインストール用コピーの説明・スキルを日本語にし、プラグインと標準MCPの両方へ`IPHONE_USE_LANGUAGE=ja`を設定します。ソース側の既定言語は書き換えません。通常版へ戻す場合は、`sh scripts/install.sh --language default`で再インストールし、チャットを再接続します。MCPの環境変数だけを変更した場合は、画面とツール説明が切り替わり、インストール済みスキルの言語は変わりません。

スクリプトはソースを検証・ステージングし、Codex CLIでローカルmarketplaceを登録してプラグインとスキルをインストールします。インストール済みサーバーを標準MCPの`iphone_use`として登録し、重複登録を避けるため同じ名前空間を使います。通常の導入ではUIの再ビルドは不要です。

再接続または新しいチャットで **iPhone Use** を有効にして、次のように依頼します。

> iphone-use-setupで、USB接続した私のiPhoneを設定し、WDAをインストール・起動してREADYを確認し、iPhoneの画面を表示してください。

診断、端末検出、署名設定、WDAの取得、バックグラウンドでのビルド・起動を行います。設定済みの端末では設定とビルドを再利用します。`pua_ready`が`ready=true`を返してからiPhone上の作業を始めます。

## できること

| 機能 | 内容 |
| --- | --- |
| アプリの移動・操作 | アプリを開き、検索・詳細・設定・下書き画面に移動 |
| 画面の読み取り | 要素ツリー、文字、位置、実際のスクリーンショットを取得 |
| タップとジェスチャー | 要素または座標でタップ、スワイプ、ドラッグ、対象の出現待ち |
| 日本語などのUnicode入力 | 完全な文章を入力し、長文は分割入力と継続トークンで処理 |
| 連続した作業 | 既知のタップ・入力・待機をbatchにまとめて往復を削減 |
| リストの検索・収集 | 上限付きスクロール、重複除去、取得範囲の明示 |
| 画面からの復旧 | 遮蔽・フォーカス不良・ツリー欠落時に画像から操作位置を判断 |
| リアルタイム画面 | iPhoneの枠、接続状態、操作時の光、タップ・ドラッグ位置を表示 |
| 接続の復旧 | 起動中のジョブやビルドを再利用し、無効なセッションを再作成 |

```text
iPhone Useで「メモ」を開き、以下の日本語で下書きを作成してください。
文字を確認して、そのまま残してください。

指定したアプリでこの名前を検索し、最初の数件を整理してください。

このリストを少しずつスクロールして読み取り、重複を除いてください。
取得できた範囲と、まだ確認できていない部分も示してください。
```

文字入力と送信は別操作です。入力ツールは既定では送信しません。重要な画面、宛先、件数、最終結果を確認します。パスワード、認証コード、Face IDなどは本人が操作し、その間はプレビューを一時停止できます。

同じチャットでは既存の画面ウィジェットを再利用します。下部のボタンは接続の更新、ホーム画面、スクリーンショットのコピーです。画像がない場合もiPhoneの枠と黒い画面を保ち、中央に状態アイコンを表示します。プレビューはユーザーが見るためのもので、モデルはツールが返した実際の画像・要素を使って判断します。

## 実装上の特徴

- ローカルのUSB通信。PythonのMCPサーバーはloopbackの転送先からWDAにアクセスし、実行データや署名・ビルドはMac内に保持します。
- HTTP接続、WDAセッション、正常なサービス、ビルドを再利用します。
- 要素ツリーの重複情報を省略し、画像だけの取得ではXMLを生成しません。batch、スクロール検索、リスト収集でツール往復を減らします。
- WDAの取得・ビルド・起動はジョブID付きで非同期に実行し、同じ設定の実行中ジョブを再利用します。
- 要素の特定に失敗したら画像を確認します。画像のピクセル座標に`image.pixel_to_point`を掛け、iPhoneのポイント座標として`pua_tap`に渡します。
- 複数プロセスで操作ロックを共有します。タイムアウトや切断で操作結果が不確実な場合は、実際の状態を読んでから続きを判断します。
- プレビューのフレームはディスクに保存しません。ロックと明示的な一時停止を区別し、更新ボタンで再接続できます。

処理全体の速さはアプリ、USB／WDAの状態、モデルの応答時間にも依存します。

## ツール

モデル向けに17個、画面ウィジェット専用に2個のツールがあります。

| ツール | 用途 |
| --- | --- |
| `pua_doctor`、`pua_setup`、`pua_ready` | 環境診断、設定、導入・起動、準備状態の確認 |
| `pua_observe`、`pua_find` | 要素ツリー、画像、対象の検索 |
| `pua_apps`、`pua_launch_app` | アプリID、インストールの証拠、アプリ起動 |
| `pua_tap`、`pua_swipe`、`pua_press_button` | タップ、スワイプ、ホームなどのボタン |
| `pua_type_text`、`pua_wait` | Unicode入力、上限付き待機 |
| `pua_batch`、`pua_scroll_find`、`pua_collect_list` | 連続操作、検索、リスト収集 |
| `pua_screen`、`pua_metrics` | プレビュー、時間・通信量の統計 |

画面の異常時はスクリーンショットを確認して次の操作を判断します。スクロール検索は1回の呼び出しで最大1回のスワイプを行い、対象が操作できなければ画像を返して止まります。遮蔽、移動未確認、入力不一致、期待したページの不在も同様です。既存の画像を再利用し、操作を無条件に繰り返しません。

## ローカルデータと更新

新規導入では`~/.local/share/iphone-use/`を使います。別の外部ディレクトリは`IPHONE_USE_STATE_DIR`で指定でき、従来の`WDA_STATE_DIR`も使えます。新しい既定ディレクトリがない場合は検出した旧設定を再利用し、端末・署名・ビルドを保持します。

実行ディレクトリの権限は700、非公開設定と画像は600です。明示的に取得した画像には保存数の上限があり、プレビューストリームはメモリ内で処理します。署名情報、端末データ、実行ログ、依存関係のインストール先はソース配布に含めません。`WDA_URL`はローカルアドレスのみ受け付け、既定の転送ポートは18100です。

```sh
git pull --ff-only
sh scripts/install.sh --language ja
```

更新後はチャットを再接続します。

日本語訳は英語READMEと同様に手動で保守します。原文の変更を確認し、必要な翻訳をPRで更新します。画面・ツール説明に対応する訳がなければ原文を表示しますが、README・スキル・参考ガイド・サーバーの操作指示は古い日本語が残る場合があるため、原文との照合が必要です。

日本語訳の追従を判定する専用CIは設けません。既存のビルドチェックは通常版と日本語版の生成物がソースと一致することを確認し、翻訳内容が最新かどうかは判定しません。

接続できないときはUSB、ロック解除、デベロッパモード、署名、setupの具体的なエラーを確認します。起動中のジョブがあれば、その状態を調べてから再起動を判断します。

## 依存関係と謝辞

[Appium](https://github.com/appium/appium)と[WebDriverAgent](https://github.com/appium/WebDriverAgent)に依存します。WDAがiPhone側の操作を実行し、[appium-ios-device](https://github.com/appium/appium-ios-device)がUSB通信、ポート転送、画面ストリーミングを提供します。iPhone UseがCodexプラグイン、MCPツール、導入ガイド、画面ウィジェットを追加します。
