# パスワードとFace IDを本人に引き継ぐ

現在の観察やツールが認証の障害を明示した場合だけ引き継ぐ。アプリのパスワード、端末コード、認証コード、Face ID／Touch ID、再ログインは本人がiPhoneで行う。空ツリーや黒い画像だけで認証と判断せず、ロック、ミラーリング、独自描画、接続障害を区別する。

## 障害を区別する

| 現在の証拠 | 対応 |
| --- | --- |
| アプリのログイン・パスワード・生体認証の表示 | そのアプリで本人に認証してもらい、端末呼び出しを止め、完了後に観察する。READYではログイン状態を証明できない。 |
| phone_lockedまたは実際のロック画面 | 本人が解除して起動状態を保ち、完了後にREADYと対象アプリを確認する。 |
| local.pid.0／pua_foreground_unavailable／XCTest Code 41 | setupスキルで接続を復旧する。アプリのパスワードエラーとみなさない。実際にシステムが要求する場合だけ信頼・認証を本人に依頼する。 |

## 引き継ぎの手順

アプリ認証なら先に`pua_screen(action="pause")`でUSBフレームの取得を止め、画像を消す。この停止はREADYやopenで自動解除されない。phone_lockedはdevice_lockedで自動停止するため、追加pauseは不要。実際の解除回答後、READY成功でそのロック停止だけを解除する。

ユーザーの更新ボタンはプレビュー再開の依頼でもある。解除確認後にクリック時点のアプリ／unknown停止を解除できるが、モデルは代わりに押さない。確認中の新たな停止は保持する。旧版の理由なし停止はunknownとして扱う。引き継ぎ中はフレーム、画像、ユーザー入力をポーリングしない。

ホストの質問機能を必ず使い、通常メッセージやfinalの「完了したら返信」だけで済ませない。実際のアプリ、止まっている手順、本人の操作、その後続ける内容を説明する。先頭選択肢は「完了したので続けてください」、次は「今は完了できません」。操作が完了したかだけを聞き、パスワード・PIN・認証コードを収集しない。

Defaultでは`functions.request_user_input_async`を優先する。実際にFace IDが表示された場合の例：

```json
{
  "questions": [{
    "title": "現在のアプリでFace ID認証が必要です。iPhoneで認証を完了し、対象の画面を開いたままにしてください。完了後に「完了したので続けてください」を選ぶと、残りの明細を読み取ります。",
    "options": ["完了したので続けてください", "今は完了できません"]
  }]
}
```

実際のアプリ、認証方式、残りの内容に合わせる。ロックなら本人に解除して起動状態を保つよう案内する。別の質問ツールがある場合はそのschemaに従い、質問のためにモードを切り替えない。質問機能がない場合だけ文章で案内し、本人の操作待ちとして未完了の状態を維持する。

非同期呼び出しは即時に戻り、完了通知ではない。本人の実際の選択または明確な完了回答まで待つ。初期選択、ツールの戻り値、時間の経過、無回答は完了ではない。すでに取得した結果の整理など独立した作業は続けられるが、端末呼び出しは再開しない。独立作業がなければ入力を待ち、質問や端末ポーリングを繰り返さず、作業全体を完了扱いにしない。

実際に見えた認証と画面だけを説明し、コードの推測や生体認証の回避をしない。認証情報をチャット、pua_type_text、batch、ログ、スクリプト、コード経由の呼び出しに入れない。通常のTextFieldとして見えても、パスワードは本人が入力する。

アプリ・画面、取得済み内容、実行済み手順、残り、操作の実行境界を保持する。認証情報は記録しない。引き継ぎ中は操作・観察・画像取得を止める。Face ID失敗や認証コード期限切れは端末の実際の提示に従い、認証やアプリ／PUAの起動を連続で繰り返さない。

## 完了後に続ける

本人が実際に「完了したので続けてください」を選んだ、または完了を明言した場合だけ続ける。アプリ認証／unknownはresume、端末ロックはREADYで対応する停止を解除する。新しい観察を一度取得し、実際の前面、認証表示、対象ページを確認する。本人がアプリ移動・スクロール・後続操作を行った可能性があるため、以前の座標、observation_id、要素IDを使わない。

まだ認証が必要なら残りの本人操作を説明して待つ。「今は完了できません」なら完了済みと残りの範囲・引き継ぎ地点を残す。キャンセルなら止める。接続障害はsetupでREADYを復旧する。アプリのセッション期限切れだけでサービスを再起動しない。

新しい状態から残りの許可済み作業を続ける。本人が済ませた送信、支払い、注文は結果を読み、重複させない。認証の完了と元の作業の完了を区別し、最後に必要なアプリ、項目、取得範囲、成果物を確認する。
