# App 快照场景说明

当某个 App 页面读树慢、节点被截断或可见文字缺失时按需读取。全局默认深度 50，模型保留单次设置深度的能力；场景参数不自动影响动作和列表采集。

## 已验证的慢列表

- 微信通讯录 / 会话列表：见 [微信长列表](wechat.md)，只读 Cell 合并文字可用 13；需要行内子节点回到 50。
- 微博「消息 → 动态」长列表：见 [微博动态](weibo.md)，只读作者 / 动态文字 / 时间可用 17；16 丢文字，17 也不能保证低于 4 秒。

## 缺信息不一定是深度问题

- 淘宝 / 拼多多 / 小红书 / 微博消息及高德搜索历史曾触及 200 个返回节点上限；`max_nodes` 是输出预算，不能减少原生树成本。按截图、目标字段、滚动范围决定是否增大输出预算（最大 500），不要因截断就降低深度或认定没有更多记录。
- 京东购物车截图有商品名称 / 规格，默认 50 的树却主要返回价格、删除等控件，商品名称不足。需要截图读取并核对；继续降低深度不能补出这些标签。
- 高德底图道路 / 地点文字并非都在树中；地图位置和覆盖层按截图判断。列表与地图不能共享“完整上下文”的假设。
- 先前小红书、支付宝首页的 20 深度对照出现字段缺失，不能迁移微信 13 或微博 17 到这些首页。

## 增补新场景

只有可复现的慢页面才新增 `references/<app>.md`。在同页加载稳定、前台正确且没有系统通知遮挡时交替测量 50 / 候选深度，记录 source 与整次工具耗时；列表增长或界面变化的轮次不能作为同页提速证据。以 50 和截图为基准，对照任务所需的每一可见行、名称、文字、数值、状态和操作入口；找到丢字段的临界档后保留安全档。较浅仍慢或字段不完整就如实记录，不强行指定浅层参数。简短写明页面、实测日期、所需字段、损失与 50 / 截图回退条件，在这里及 SKILL.md 加按需入口；不要收录个人消息、联系人姓名、地址等测试原文。
