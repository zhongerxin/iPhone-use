# 微信长列表

仅在微信「通讯录」或首页「微信」会话列表读树慢时使用；不套用于聊天正文、朋友圈、设置或其他 App。全局默认仍为 50。

## 按所需字段选择深度

- 读取联系人姓名、会话名称 / 最新消息摘要 / 时间 / 未读或置顶状态时，可先用 `pua_observe(mode="tree", snapshot_max_depth=13)`；需对照当前可见行时用 `mode="both"`。从 `Cell.label` 读取合并文本，不要求其内部 `StaticText` 存在。
- 13 是本次实测保留列表行的最低档；12 会丢掉全部 Cell，不能用于读取联系人或会话。仅导航且已经知道目标位置时，可只取 screenshot，跳过 XML。
- 13 会省略行内头像、独立文字 / 图标及部分分组、索引节点。需要这些字段、Cell 标签不够用、所需可见行缺失或微信页面结构变化时，查看截图并用 50 重读。不要为了提速继续降低到 12。
- 单次参数只改变独立观察，不会使后续 selector 查询、动作后的观察或 `pua_collect_list` 自动采用 13；这些仍默认 50。不要为了维持浅层设置直接修改原生会话。
- 固定顶部 / 底部可能遮挡树中的行，顶部还存在离屏子节点坐标异常。13 不是“只读可见区域”，不能凭 `total_nodes`、节点出现在树里或采集停止判断全量、可点击或已到底；仍按截图和任务范围核对。

## 实测依据

2026-10-11 当前真机、微信 8.0.79，children 不限制，visible / accessible 昂贵查询关闭，交替比较不同深度。source 请求约：会话列表 50 通常约 4–6 秒（本次有单轮约 9.7 秒）、13 约 1–3 秒；通讯录 50 为 5–7 秒、13 约 1 秒。14 仍明显慢于 13，16 / 20 没有有效解决长列表耗时。时间随列表、设备和缓存变化，不能作为所有微信版本的保证。

通讯录顶部、中部 L 段、尾部 # 段以及会话列表顶部 / 滚动后均已核对。50 / 13 的原始 Cell 数分别保持一致：会话列表 1,493，通讯录 1,559；同页 Cell 的 label / name / value 对照相同。13 省略更深的行内子树，12 连 Cell 都截掉。默认返回最多 200 个过滤后节点，是另一层限制，不能用它衡量原生快照成本。

原生深度有效范围 1..62，较低深度可能提速并省略深层内容，见 [Appium 官方设置说明](https://appium.github.io/appium-xcuitest-driver/12.0/reference/settings/#snapshotmaxdepth)。以上 13 的选择来自本次真机对照，不能从 XML 层数直接推算，也不应成为全局默认。
