# 手机认证后自动继续

密码、PIN、验证码、Face ID / Touch ID 和设备解锁由用户在手机上完成。不索取、记录或代填密码。

## 自动等待

1. 从已有观察记住目标 App、认证标题和已知的目标页标记。不要保存输入值。
2. App 认证调用 `pua_screen(action="pause")`，停止预览、动作和普通读取。`phone_locked` 已记录 `device_locked`，不要再 pause 覆盖原因。
3. 用简短进度提示说明：「请在 iPhone 上完成认证，完成后我会自动继续。」不调用宿主完成确认问题，也不要求用户回到宿主点击恢复。
4. App 认证调用 `pua_screen(action="wait_auth", bundle_id="实际目标App", ready_label="已知目标页的非输入控件标签", timeout=25)`。优先选认证后独有的标记；也可传 `auth_label="已有观察中的认证标题"`，检查该标题消失。两者可同时传入。不得传密码、验证码或猜测标签。
5. 设备锁屏直接调用 `pua_screen(action="wait_auth", timeout=25)`。探测实际解锁，不要求聊天通知。
6. `state="waiting_auth"` 时继续调用同样的有界等待，保持任务活跃；用户发来停止或取消指令时停止。每轮至多 25 秒，不添加周期提醒或重复接管通知。需要较长等待时用简短进度保持沟通，不要求用户确认。
7. `paused=false` 后获取一次新观察；设备解锁后重验 READY。重新定位当前 App 和页面，继续剩余已授权工作，不复用旧坐标、元素 ID 或输入续传。

`wait_auth` 只查询解锁状态、前台 App 和控件存在性。存在性查询使用 compact ID 响应，不返回标签、字段值、树或图片。预览和常规操作在等待期间保持暂停。只有连续两次检测到符合条件的状态，才清除同一 ID 和代次的暂停。锁屏、其他 App、键盘、可见安全输入框、Alert / Sheet、通道错误或新暂停均不能自动恢复。

## 结果边界

`auth_ui_cleared` 表示认证界面已退出，不证明认证成功。用户也可能取消、返回上一页或已完成后续操作。必须用新观察判断剩余工作，不能重复发送、支付、下单或重放整个批次。原任务的权限和提交边界仍有效。

`auth_target_required` 表示缺少可靠的页面标记，先从已有任务上下文补齐。自绘密码页没有可识别标记时，不用空树或时间经过来推断完成；说明该页面暂不支持自动检测。`probe_unavailable` 表示通道或探测异常，只诊断服务状态，不自动重启 App 或反复触发认证。`pause_changed` 表示其他调用改变了接管状态，按最新暂停原因重新判断，不清除新暂停。

旧版 `unknown` 暂停也可在目标 App 和页面条件明确时使用 `wait_auth`。无法检测时保留暂停，并说明真实缺项。`resume` 是 `wait_auth` 的兼容别名，执行同样的手机证据检查；没有证据时任何调用都不能解除暂停。需要补充目标 App 等信息时，宿主提问工具可按实际需要使用；不能把缺少信息当作完成确认。

## 服务端限制

暂停状态由本机进程共享。普通读取、截图、手势、输入和批处理仍被阻断；在途读取不回传，可能已发送的动作保持不确定且不得重放。认证探测仅允许固定的状态、设置和控件存在性请求，串行使用操作锁；设置恢复失败时保持暂停。不发送手机动作，不创建新会话，不重建服务。不把探测成功称为任务完成。
