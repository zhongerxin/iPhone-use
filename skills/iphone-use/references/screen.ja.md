# iPhoneの画面プレビューと復旧

ウィジェットはユーザー用の画面表示で、モデルはツールが返す実際の観察を使う。Live、キャッシュ、光、ジェスチャー表示はREADYや作業完了の証拠ではない。同じチャットのパネルを開く・停止・再開・再接続する。すでに開いていれば再利用し、閉じた場合だけ`pua_screen()`を一度呼ぶ。

## 画面がない・一時停止の場合

- 最初のフレーム前の`frame_available=false`は接続失敗の証拠ではない。プレビューは操作接続とは別のUSB MJPEG。操作できるのに画像がないだけで、PUA再起動、session再作成、画像の連続取得をしない。
- 有効なフレームがないときはiPhoneの枠と黒い画面を残し、接続・ロック・認証・停止・取得不可のアイコンを表示する。一時的な切断では最後の画像を保持するが、現在の状態の証拠ではない。
- preview.paused=trueならpause_reasonを読む。device_lockedは本人の解除を待ってREADY、authenticationや旧unknownは[認証ガイド](authentication.ja.md)で実際の完了回答を待ってresume。
- ユーザーは更新ボタンでプレビューを再接続できる。解除確認が成功した場合はクリック時点の停止を解除し、確認中に起きた新しい停止は保持する。更新はPUAの再起動、操作sessionの再作成、端末ジェスチャーを行わない。モデルはApp専用のボタンツールを代わりに呼ばない。
- 更新後はチャットを再接続し、古い画面を閉じて`pua_screen()`で新リソースを開く。画面更新のためだけにPUAを再導入・再起動しない。

操作ツールの接続エラーは[起動と復旧](startup.ja.md)、位置の特定失敗は主スキルの画像・座標手順に従う。

## 認証とツールの範囲

パスワード、PIN、認証コード、Face ID／Touch IDでは[引き継ぎ](authentication.ja.md)を行い、端末操作・読み取り・画像取得を止める。画面を開くことやREADY成功はアプリ認証の完了ではない。実際の完了回答後に新しい観察から進め、古い座標や有効かもしれない業務操作を再利用・再実行しない。

`pua_screen_frame`と`pua_screen_action`はApp専用。更新、Home、スクリーンショットはユーザーが押す。認証停止中はHomeと画像コピーが無効になる。非表示・終了でフレーム取得を止め、認証停止で実際の画像を消す。

## 同梱されるソース

`assets/phone-screen.html`は単体で動作する。完全なuiソース、CSS、依存ロック、ビルド設定、テストも含む。通常の導入では再ビルド不要。変更時は次を使う。

```sh
npm ci --prefix ui --no-audit --no-fund
npm run build --prefix ui
python3 scripts/check_screen_ui.py
```

UIはCDNや遠隔フォントに依存しない。USBストリームのスクリプトとtoolingの依存定義も同梱される。docsとevalsは上流のローカル開発資料で、実行には不要。
